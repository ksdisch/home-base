# The thin day says so in the channel that reaches the phone first

**Status:** Idea — not committed. Added by `/replenish` (QuickWin lane) on 2026-08-12.
**Note:** Cross-lane overlap flagged at review: `dont-send-half-a-brief` (Harden) includes the same partial-day labeling — if both are built, they merge into one implementation (gate + label).

_One roster-diff line — computed by the page's exact "didn't run" rule — appended to the iMessage caption, the email HTML digest, and the spoken MP3, so a morning where six of eight topics failed can't arrive looking like a quiet news day._

## Premise

`GET /api/brief` has computed `missing_topics` since QU12 (`backend/app/api/brief.py:150-157`), and Today renders it as a warning Banner reading "N topics didn't run today" — so on the web page a crashed topic and a quiet one are visibly different things. PRs #181/#183 then put an email plus a tap-to-play iMessage in front of that page: those two messages, and the MP3 they carry, are now the first contact every morning, and none of the three carries the signal. On 2026-08-09 the day folder holds six `.raw.txt` validation failures beside two rendered topics; the delivery went out naming "2 topics: Fantasy football · St. Louis Blues" and said nothing about the other six. The move is to carry the page's honesty across the lane boundary: teach `sweeps/audio_brief.py:49`'s `load_roster` to keep the `paused` flag it currently drops, add one helper that names the active roster topics with no renderable file for the day, and append its result to `build_caption()`, `build_html()`, and `build_script()`. The rule must be the page's rule (any non-dotted-stem `.json`/`.md` present), not the audio lane's narratable-JSON rule — 2026-07-13 holds three `.md`-only topics that render fine on the page and would otherwise be libelled as failures. Zero LLM, zero network, stdlib-only, no config key, no schema change.

**Why now:** The extended v1 verdict lands ~2026-08-19 and certifies on `mornings_phone` ≥5 with supply checked first (D12/F8) — the whole judgment turns on separating "the sweep was thin" from "Kyle skipped". Right now the morning that reaches the phone is precisely the surface that hides thinness, so the outage weeks the verdict is supposed to discount arrive indistinguishable from quiet ones. 08-09 already happened and already lied by omission; the window has ~a week of graded mornings left, and this is a one-sitting change to the lane that produces them.

## The bet

The one thing that must be true: per-topic sweep failure is a recurring partial event, not an all-or-nothing outage — verified in the data (2026-08-09: 6 of 8 topics `.raw.txt`; 2026-08-10: 3 of 8), and the delivered message now outranks the page as first contact, so a thin message that can't admit it's thin is what actually teaches Kyle that a short day is just a short day. Two things make a veteran of this project flinch. First, it deliberately puts a failure notice into the one Home Base artifact that can never be corrected once sent — a wrong "3 topics didn't run" in an already-delivered iMessage is permanent, which is exactly why the paused-flag fix is a prerequisite and not a polish item (without it, the three off-season topics paused on 08-11 get reported as failures every single morning). Second, it creates a SECOND implementation of "didn't run": the sweeps lane is stdlib-only system python3 and cannot import `backend.app.sweeps`, so the rule gets duplicated and can silently drift from the page it's supposed to agree with. The answer is not to soften the line but to pin it — one parity test asserting the sweeps-lane missing set equals the backend's `missing_topics` over the same synthetic day dir, using the `sys.path.insert` import pattern `backend/tests/test_deliver_brief.py:199-202` already uses.

## Decisions / open questions

- Wording parity: reuse Today's exact phrasing ("N topics didn't run today" + titles joined by ·) so the message and the page can't disagree in tone — recommended yes; a second vocabulary for the same fact is how the two lanes start drifting in meaning even when the code agrees.
- Does the line ride in the MP3 itself, or stay text-only? Recommended: include it — `build_script` takes an optional arg, chapter math is untouched, and the audio is what the tap-to-play link actually delivers. Text-only honesty in a message whose whole payload is audio is a half-measure.
- A topic that produced only `.raw.txt` (ran, failed validation) vs one that never produced anything: the page does not distinguish them today. Recommended: match the page now and revisit both surfaces together — inventing a distinction here breaks the parity test's premise.
- Total-failure morning: zero narratable topics means no brief.mp3, so `deliver_brief` exits "nothing to send" and Kyle gets complete silence — indistinguishable from a sleeping Mac. Real gap, deliberately left to the sibling completeness-floor idea rather than smuggled in here.
- Roster is read at send time, so a topic paused after its sweep failed drops off the list. Recommended: accept — it is exactly what the page does for the same day.
- Where the shared rule lives: a third loader copy inside `audio_brief.py` (which `deliver_brief` already imports) vs a new `sweeps/roster.py`. Recommended: keep it in `audio_brief.py` and let the parity test carry the weight; a new module for one predicate is the kind of abstraction this repo doesn't need.

## Credible first step

(1) `sweeps/audio_brief.py:49` — `load_roster` currently builds `{slug, title}` only (confirmed live: keys are `['slug','title']`); add `"paused": bool(entry.get("paused"))`, mirroring `backend/app/sweeps.py:28`. Safe: `load_topics` (lines 119-123) reads only `slug`/`title`, and `sweeps/actions_queue.py:71` keeps its own separate copy. (2) New helper in `sweeps/audio_brief.py`, e.g. `missing_topics(day_dir, roster) -> list[dict]`: active (non-paused) roster entries whose slug has no `.json`/`.md` file with a dot-free stem in the day dir — the same rule as `backend/app/sweeps.py:704-711` + `_is_topic_stem` (line 63) + `api/brief.py:150-157`, deliberately NOT `load_topics`'s narratable rule. (3) `sweeps/deliver_brief.py:303` already loads roster + topics one line before `build_caption` (line 257) and the `send_email` call that feeds `build_html` (line 154) — thread the helper's result into both: one caption line ("⚠️ 3 topics didn't run: A · B · C") and one leading `<p>` in the HTML digest. (4) `build_script` (`sweeps/audio_brief.py:140`) gains `missing: list[str] = []` and speaks one sentence before the closer; `audio_brief.main:252` and `deliver_brief.main:304` pass it. Chapter offsets are unaffected — they sum only the opener and per-topic segments (lines 181-191). (5) Tests: `backend/tests/test_deliver_brief.py::_setup` currently hardcodes a one-topic roster (lines 61-64) — give it a `roster=` param, then a partial-day case (`{"ai-llms.raw.txt": "..."}` plus a paused entry) asserting the caption and HTML name the failed titles and never the paused one; `backend/tests/test_audio_brief_script.py::_setup` already takes `roster=`/`files=` and `--print-script` gives a clean assertion surface for the spoken line; add the one cross-lane parity test described in the bet.

## Dependencies

`sweeps/audio_brief.py` (`load_roster`, `load_topics`, `build_script`) and `sweeps/deliver_brief.py`'s existing `import audio_brief` at line 50 — both stdlib-only, system python3, no venv. `sweeps/topics.json` pause flags (currently 3 of 8 paused: celtics, kansas-basketball, st-louis-blues). `backend/app/sweeps.py` + `api/brief.py:150-157` as the rule of record the parity test compares against. Existing no-network test seams: `DELIVERY_SMTP_PASSWORD`, the `DELIVERY_OSASCRIPT` recording stub, and `--print-script`. No new config key, no LLM lane, no schema or endpoint change.

## Explicitly out of scope (revisit later)

No gate on whether to send — no `min_coverage`/`min_topics` threshold, no holding a partial brief for the catch-up, no subject-line change (that is the sibling completeness-floor idea, which should consume this helper rather than re-derive it). No surfacing of the delivery ledger back onto Today (the delivery-receipt idea). No retrying or re-running failed topics, and no change to how sweeps validate or write files. No new wording that distinguishes `.raw.txt` from never-produced. No unifying the three roster loaders — `sweeps/actions_queue.py:71` stays exactly as it is. No new notification channel, and no per-day history of which topics failed.

## Identity/positioning note

none — tethered. It extends a shipped in-app honesty guarantee (QU12) to two shipped channels, in the spirit of the #182 "no surface states a guarantee the code doesn't keep" fixes.

## What it changes

Every delivered morning: the iMessage caption, the email's HTML digest, and the narration inside brief.mp3 each gain one line naming the active topics that produced nothing. The sweeps lane gains its first explicit "did this topic run" rule, held to the page's definition by a parity test. Because `audio_brief.is_fresh` re-renders when a late topic lands and `_delivered_channels` re-sends on a regenerated mp3, the claim self-corrects: a 06:00 message that says "3 didn't run" is followed by a catch-up message that says "1 didn't run" rather than standing as a stale accusation. Nothing about sweeping, validation, the delivery ledger schema, or any API/frontend surface changes.
