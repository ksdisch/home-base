# Bug hunt — 2026-08-12 — post-07-26 delta (delivery lane · archive/audio · studycal v1.1–1.3 · paths/step-kinds · brief backend · For You/News · contract drift)

**Scope:** the ~40 commits merged since the [2026-07-26 report](2026-07-26-post-studycal-m8.md) (base d447174). Run as Lane A of a 4-lane `/replenish` (ultracode fan-out): 7 finders (subsystem × lens, incl. the dedicated `silent-failure-hunter` and `contract-reviewer` agents) → adversarial verify-each (batched, default-refuted) → synthesis. 27 findings confirmed out of the finders' raw claims; the synthesizer merged same-defect pairs to the **22 ranked findings** below. Known-open bugs #6/#15/#17/#18/#19 from the 07-26 hunt were excluded by construction; nothing here re-reports them.

**Disposition:** triage-only — nothing was fixed in this run. Cross-cutting themes first; they are worth more than any single fix.

## Themes

- **Honesty-of-readouts is regressing faster than it's being fixed** — the single largest cluster (ranks 3, 4, 6, 8, 13, 21, plus 20's silent bullet). Every one is a surface asserting something the data doesn't support: a healthy in-flight sweep labelled 'thin or half-failed', '0p' phone mornings for weeks that predate attribution, a hand-authored path's bridge step captioned 'Generated… this topic has no study guide' next to its own Read step, a total For-You outage rendered as 'this section came back empty', stale hits under a new query, and a banner saying Generate ships 'in a later phase'. #182 fixed two instances of exactly this and known-open #19 is a third — the pattern is that copy and computed flags are hardcoded or unconditional instead of derived from the state they describe. `mirror.py`'s `attributed` gate is the house pattern that the rest of the codebase hasn't adopted.
- **Singleton assumptions broken by the arrival of a second instance.** Code written when there was exactly one of something still assumes one, and the delta under hunt added the second of nearly everything: a second BriefAudioCard (archive) fights the shell card over `navigator.mediaSession` and over playback rate (rank 10); a second learning path (#173) exposes the cross-path busy filter (rank 12), the video/mindmap icon maps (rank 20), and the 'only path that exists' copy (rank 21); a second surface for audio exposes the missing `retryKey` wiring (rank 14). Worth a standing check: when a feature gains a second instance, grep for every place the first one's uniqueness was assumed.
- **No validation at the parse → config → planner seam.** The studycal chain lets values cross module boundaries that the receiving module cannot represent: an hour clamped to `(1, 24)` handed to `datetime.replace` which accepts 0–23 (rank 1); negated phrases producing inverted or one-hour windows (rank 5); a per-day quantifier mapped onto the total-window cap because the parser's output vocabulary and the planner's config vocabulary were never reconciled (rank 16). The repair logic (`min(24, start+1)`) actively manufactures the illegal value rather than rejecting the input, and the persist-before-plan ordering then makes bad input durable.
- **Narrow exception nets around I/O bypass the degrade paths they were built to feed.** Catch-by-specific-type appears everywhere and consistently lets the unexpected class through: `except NewsFeedError` at four layers means one `IncompleteRead` 500s the whole news path instead of serving stale cache (rank 7); `except CalendarNotConnected` lets a mid-loop Google error escape as a bare 500 with the ledger un-flipped (rank 11); `except OSError: pass` silently keeps a truncated backup (rank 18). In each case a designed honest-degrade branch exists and is skipped exactly when it was needed.
- **Write-then-record ordering with no compensating rollback.** Four findings leave a durable half-state that later reads treat as truth: the note is committed before its ledger row (rank 17), calendar events are deleted before the ledger is flipped (rank 11), the path sidecar is `os.replace`d with no prior backup (rank 2), and the snapshot is copied straight to its final name (rank 18). The house has a good pattern for this — confirm's create-one/ledger-one loop and its partial-write copy — that these sites didn't follow.
- **Cleanup and reset keyed to the happy-path event that may never arrive.** State that should be per-attempt outlives the attempt: `pendingSeek` is cleared only by a `loadedmetadata` that a failed load never fires (rank 15); search `results`/`error` are cleared only by a successful response (rank 13); `broken` is cleared only by a `retryKey` the archive never passes (rank 14); mediaSession handlers are nulled by whichever card unmounts last rather than by whoever owns them (rank 10). Each is a missing reset on the failure edge, not a wrong success path.
- **The test suites pin the single-instance happy path — and in one case pin the bug.** Nearly every finding carries 'no test covers this': two mounted cards, a rejected search, hour=24, an incomplete current day, a non-NewsFeedError raise, a router-level remove failure, an id case mismatch. The parallel-fanout test asserts a bound loose enough to pass with three waves, and `test_visit_source.py:295-322` actively asserts `mornings_phone == 0` for an unattributed week, so fixing rank 4 requires changing a green test. Coverage is being written to confirm the design rather than to attack it.

## Ranked findings

### 1. 🟧 [high] day_end_hour=24 crashes the planner — propose 500s, and the bad window is persisted first so it keeps 500ing

- **Where:** `backend/app/studycal/planner.py:75 (reached from backend/app/api/study.py:74, 286-291 and backend/app/studycal/negotiate.py:145-147)`  · dimension: studycal
- **Why it matters:** Spot-checked and confirmed: `_local_window` is literally `day.replace(hour=hour, minute=0, second=0, microsecond=0)`, which raises `ValueError: hour must be in 0..23` for 24, while three independent callers clamp `day_end_hour` to (1, 24) and repair inverted windows with `min(24, day_start+1)`. The finder reproduced a hard 500 through the real router on three routes (explicit body, local parser on a 23:00 start, negotiate lane returning 24), and — the part that makes this the top item — `set_study_prefs` runs BEFORE `plan_sessions`, so the poisoned 23/24 window is persisted and every later propose, even with an empty body, 500s. Recovery is non-obvious: end-only changes re-yield 24, and PathPlayer's selects top out at 20/22 so the panel literally cannot send a start hour low enough to clear it. Only hard 500 in the set, with no honest degrade and durable bad state. `_events_in_window` already uses the midnight+timedelta form that would be safe, so the fix is one line.
- **Suggested fix:** Make `_local_window` hour-24-safe (`day.replace(hour=0,minute=0,second=0,microsecond=0) + timedelta(hours=hour)`), mirroring `_events_in_window`; add a regression test at hour=24 and a repair path for already-persisted 23/24 prefs.

### 5. 🟨 [medium] Negated time preferences are parsed backwards — "nothing after 3pm" becomes a 3pm START, "not before 2pm" collapses the day to one hour

- **Where:** `backend/app/studycal/parse.py:62-63 (searched at 180-185)`  · dimension: studycal
- **Merged from:** "Parser inverts "nothing after 3pm" into a 3pm START — schedules precisely the hours the learner ruled out" · ""not before 2pm" / "not until 3pm" set day_end == day_start, silently collapsing the day to one hour"
- **Why it matters:** MERGED: two confirmed findings, one underlying defect in `_parse_window` — the trigger regexes are blind to the negation context around them, and one pass fixes both. (a) `_START_TRIG` guards `after` with only `(?<!not )(?<!no )`, so 'nothing after 3pm' / 'never after 3pm' / 'no sessions after 3pm' all yield `day_start_hour: 15` — scheduling precisely the hours ruled out; through the real router that persisted a 15–16 window. (b) `_END_TRIG` carries bare `before|until` and the end search runs over the untouched text (verified: the START search at line 180 does not blank its match), so the END pattern fires INSIDE the start phrase — 'not before 2pm' → {14, 14}, 'evenings but not before 7pm' → {19, 19}, destroying the named window's end. Kept at medium (not high) because propose is read-only, the wrong window is echoed in `applied` and rendered in the panel summary, and nothing reaches Google without a separate confirm — a visible mis-parse, not a silent wrong write. Existing tests cover only the unnegated forms; one test deliberately asserts a narrower property of 'not before 2pm' and leaves the spurious `day_end_hour` unguarded.
- **Suggested fix:** Blank the START match out of the text before running the END search (the trick `_parse_days` already uses for exclusions), and replace the two literal lookbehinds with a real negation guard (`not|no|never|nothing|none` within a small window) applied to `after`, `before`, `until` and `by` alike.
