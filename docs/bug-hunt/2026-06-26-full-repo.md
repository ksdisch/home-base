## Themes

- **Silent degradation on uncovered edges is the meta-pattern.** Every confirmed bug fails quietly (wrong/missing dates, dropped content, collapsed or phantom rows, contradictory banners), and every trigger — duplicate stems, BOM, bracketed logs, truncated ids, injected `now`, unbalanced fences — is precisely a case with **zero test coverage**.
- **Timezone/timestamp handling is inconsistent across the API seam.** The backend writes naive-UTC SQLite `datetime('now')` strings for DB fields but offset-bearing ISO-8601 for every `*Response.generated_at`; the frontend's single `shortDate()` normalizes neither, so dates drift off-by-one in opposite directions depending on the shape.
- **The SM-2 / mastery store carries several silent data-integrity edge cases**, all in the spaced-repetition path and all untested for the degenerate case (duplicate-text key collisions, `miss_count` never resetting, injected-`now` half-propagation).
- **Catalog ingestion is brittle to imperfect human/tool input** — truncated ids double artifacts, a BOM defeats frontmatter + map JSON, a bracketed log line breaks studio-status recovery. Each is a guard built to tolerate mess that misses one adjacent case.
- **Progress-page (and frontend) state is over-coupled and inconsistently guarded** — the whole dashboard nested under one endpoint's `has_data`, three fetches fused with `Promise.all`, and several effects never clear a stale `error` before refetching.

## Calibration

No false positives remained: all survivors were traced to exact `file:line` and the higher-impact ones empirically reproduced (path traversal, BOM, reconcile doubling, timezone parsing, `miss_count`, SHA1 collision each run live). The verifier was conservative — it downgraded six original severities (five medium→low) and pruned over-stated scope — so this set is calibrated-low rather than inflated. The only dedupe merged the two `shortDate`/timezone reports sharing one root cause (13 → 12 distinct).

## Actioned

Finding **#1** (the only medium) was handed to `systematic-debugging` and fixed in this PR: failing regression test first (`frontend/src/pages/Progress.test.tsx`), then a root-cause fix that decouples each section's visibility from quiz attempts (self-guarding sections + activity strip render on their own data; the empty-state banner shows only when nothing has data). Verified green — 13/13 frontend tests, typecheck clean.

The remaining 11 lows are recorded here for triage. None are urgent — all are silent and low-impact — but #4 (path traversal) is the cheapest high-value fix if a hardening pass is wanted, and #2/#11 sit in the same `Progress.tsx` / date-handling area touched here.
